# وکیل‌یار هوشمند

نسخه اولیه وب‌اپلیکیشن فارسی برای ارائه اطلاعات عمومی حقوقی.

## امکانات نسخه اولیه
- رابط فارسی و راست‌چین
- دریافت پرسش از مسیر `POST /api/chat`
- نمایش سهمیه از مسیر `GET /api/usage`
- ارسال پرسش به وکیل از مسیر `POST /api/questions/create` (نیازمند تنظیمات Redis و ثبت وکیل فعال)
- حذف امن پرسش و پاسخ‌های متعلق به کاربر از مسیر `POST /api/questions/mine` (فقط مالک پرسش؛ نمایش فهرست با GET)
- اتصال اختیاری به API سازگار با قالب OpenAI Chat Completions
- عدم نمایش پاسخ ساختگی در صورت تنظیم نبودن موتور هوش مصنوعی

## استقرار روی Vercel
1. مخزن `vakilyar-smart` را در Vercel وارد کنید.
2. Framework Preset را روی Other و Root Directory را روی `./` قرار دهید.
3. Deploy را اجرا کنید.
4. پس از استقرار، صفحه اصلی را باز کنید و برای بررسی وضعیت موتور هوش مصنوعی، یک پرسش آزمایشی غیرحساس ارسال کنید. مسیر `GET /api/usage` وضعیت سهمیه را نشان می‌دهد؛ این مسیر به تنظیمات `APP_SECRET` و Upstash نیاز دارد.

## فعال‌سازی موتور هوش مصنوعی
در Vercel از Settings > Environment Variables این متغیرها را تعریف کنید:
- `AI_API_KEY`: کلید محرمانه سرویس‌دهنده
- `AI_API_URL`: نشانی endpoint سازگار (اختیاری؛ پیش‌فرض Groq Chat Completions)
- `AI_MODEL`: نام مدل (اختیاری؛ پیش‌فرض `openai/gpt-oss-20b` در Groq)

پس از افزودن یا تغییر متغیرها، یک Redeploy انجام دهید. کلید API را هرگز در کد، مخزن عمومی یا گفتگو قرار ندهید.

## اجرای محلی
به Node.js نسخه 22 یا بالاتر و Vercel CLI نیاز است:
```bash
npm install -g vercel
vercel dev
```

## حریم خصوصی و محدودیت
متن گفت‌وگوی عادی با موتور هوش مصنوعی در این نسخه در پایگاه داده ذخیره نمی‌شود؛ اما پرسش‌هایی که کاربر با رضایت صریح برای وکیل ارسال می‌کند، همراه با پاسخ‌های وکیل در Upstash Redis نگهداری می‌شوند. برای پرونده‌های پرسش، زمان انقضای خودکار با متغیر اختیاری `QUESTION_RETENTION_DAYS` تنظیم می‌شود (پیش‌فرض ۹۰ روز؛ بازه مجاز ۱ تا ۳۶۵۰ روز). پاسخ وکیل زمان انقضای اولیه پرونده را حفظ می‌کند و آن را تمدید نمی‌کند. حذف دستی توسط مالک نیز فراهم است. این TTL اولیه، جایگزین سیاست جامع نگهداری داده، حذف از نسخه‌های پشتیبان/گزارش‌ها یا بررسی حقوقی الزامات حریم خصوصی نیست؛ این موارد پیش از عرضه عمومی باید جداگانه بررسی شوند. برای نسخه آزمایشی، محدودسازی نرخ درخواست در گفت‌وگوی عمومی، ارسال پرسش به وکیل، ورود وکیل، پنل‌های مدیریتی، بررسی سهمیه، فهرست وکلا، پروفایل وکیل، صندوق پرسش‌ها، ثبت پاسخ، مشاهده تاریخچه و حذف پرسش‌ها پیاده‌سازی شده است؛ شناسه IP در کلیدهای محدودسازی نرخ درخواست به‌صورت HMAC نگهداری می‌شود و نشانی خام در پایگاه داده برنامه ذخیره نمی‌شود. محدودیت تلاش ورود وکیل نیز با HMAC ترکیبی از ایمیل و IP اعمال می‌شود تا یک اتصال نتواند حساب وکیل را برای سایر اتصال‌ها قفل کند؛ ایمیل خام در کلید محدودسازی ذخیره نمی‌شود. با این حال، پایش سوءاستفاده، بررسی جامع امنیت، سیاست پشتیبان‌گیری و حذف داده از گزارش‌ها/نسخه‌های پشتیبان و تطبیق حقوقی نهایی هنوز پیش از عرضه عمومی لازم است. این سامانه جایگزین وکیل دارای پروانه نیست.


## سهمیه حجمی و پلن وکیل‌یار (نسخه آزمایشی)

- حوزه پیش‌فرض همه کاربران، قوانین جمهوری اسلامی ایران است.
- کاربر رایگان با اعتبار حجمی اولیه (پیش‌فرض ۱۰۰۰ واحد) کار می‌کند.
- هزینه پایه هر پرسش ۱۰ واحد است؛ درخواست‌های شناسایی‌شده به‌عنوان تحلیل قرارداد ۱۰۰ واحد و تحلیل سند/متن بلند ۱۵۰ یا ۳۰ واحد مصرف می‌کنند.
- درخواست حقوق بین‌الملل یا قوانین کشور دیگر برای حساب رایگان با کد `PRO_REQUIRED` متوقف می‌شود.
- مسیر `GET /api/usage` موجودی اعتبار و وضعیت پلن را برمی‌گرداند.
- مسیر `POST /api/chat` سهمیه را در سمت سرور کنترل می‌کند. رزرو، بازپرداخت و نهایی‌سازی اعتبار با شناسه یکتای درخواست و عملیات اتمی Redis انجام می‌شود تا تکرار درخواست پس از timeout باعث کسر یا بازپرداخت دوباره نشود.

### متغیرهای لازم برای سهمیه‌بندی

در Vercel، این متغیرها را در Environment Variables تعریف کنید:

- `APP_SECRET`: یک مقدار تصادفی و محرمانه و طولانی برای امضای شناسه کاربر.
- `UPSTASH_REDIS_REST_URL`: نشانی REST پایگاه داده Upstash Redis.
- `UPSTASH_REDIS_REST_TOKEN`: توکن محرمانه همان پایگاه داده.
- `FREE_CREDITS_INITIAL`: اعتبار شروع کاربر رایگان؛ پیش‌فرض ۱۰۰۰.

این متغیرها را در کد یا مخزن عمومی قرار ندهید. تا پیش از تنظیم APP_SECRET و Upstash، API سهمیه با خطای پیکربندی متوقف می‌شود و سهمیه‌بندی را دور نمی‌زند.

### وضعیت وکیل‌یار پرو

در این مرحله، قفل سمت سرور برای قابلیت‌های بین‌المللی ایجاد شده، اما احراز هویت کامل، درگاه پرداخت و فعال‌سازی خودکار اشتراک هنوز پیاده‌سازی نشده‌اند. وضعیت پرو در Redis با کلید `vy:user:<account_id>:pro` و مقدار `active` نگهداری می‌شود؛ فعال‌سازی دستی صرفاً برای آزمایش مدیریتی است و قبل از عرضه عمومی باید به سامانه اشتراک و احراز هویت امن متصل شود.

اعتبارهای مصرفی و هزینه‌های هر نوع درخواست، اعداد اولیه آزمایشی‌اند و باید با اندازه‌گیری مصرف واقعی مدل و هزینه سرویس تنظیم شوند.


### هدیه اعتبار توسط مدیر

- پنل مدیریتی آزمایشی در مسیر `/admin-credits.html` قرار دارد.
- مدیر با متغیر محرمانه `ADMIN_API_KEY` از طریق هدر Bearer احراز هویت می‌شود.
- مدیر می‌تواند با `POST /api/admin/grant-credits` به شناسه کاربر اعتبار اضافه کند یا با `unlimited: true` مصرف حجمی را برای او نامحدود کند.
- با `unlimited: false` می‌توان هدیه نامحدود را لغو کرد. این عمل اعتبار عددی باقی‌مانده را حذف نمی‌کند.
- شناسه مرجع تصادفی و غیرشخصی کاربر در پاسخ `GET /api/usage` با فیلد `account_id` برگردانده می‌شود؛ این شناسه به‌تنهایی مجوز دسترسی به حساب نیست و عملیات مدیریتی همچنان به `ADMIN_API_KEY` نیاز دارد.
- هدیه نامحدود فقط سهمیه حجمی را نامحدود می‌کند و به‌تنهایی امکانات حقوق بین‌الملل/کشورهای دیگر یا اشتراک Pro را فعال نمی‌کند.
- عملیات هدیه و تغییرات مدیریتی در فهرست ممیزی Redis ثبت می‌شوند؛ پنل مدیریت وکلا امکان مشاهده ۱۰۰ رویداد اخیر را دارد و فهرست در Redis حداکثر ۵۰۰ رویداد را نگه می‌دارد.
- برای فعال‌سازی دستی Pro در نسخه آزمایشی، مدیر می‌تواند همان endpoint را با بدنه `{"action":"set_pro","user_id":"<account_id>","active":true}` فراخوانی کند؛ برای لغو، مقدار `active:false` بفرستد. این عملیات نیز در فهرست ممیزی ثبت می‌شود.
- پیش از فعال‌سازی Pro، شناسه کاربر را از `GET /api/usage` دریافت و با عملیات `{"action":"lookup","user_id":"<account_id>"}` بررسی کنید. هرگز کلید مدیر را در مرورگر عمومی، کد سمت کاربر یا گفتگو قرار ندهید.

متغیر جدید لازم: `ADMIN_API_KEY`؛ آن را فقط در تنظیمات محرمانه Vercel قرار دهید و برای آن حداقل ۳۲ نویسه تصادفی به‌کار ببرید. صفحه مدیریت عمومی است اما عملیات سمت سرور بدون کلید مدیر معتبر رد می‌شود. برای عرضه عمومی، بهتر است صفحه مدیریت پشت احراز هویت مدیر و محدودیت دسترسی قرار گیرد.

### مدیریت حساب و دسترسی وکلا

- پنل `/admin-lawyers.html` برای ایجاد حساب مستقل وکیل، فهرست وکلا، ثبت/بازنشانی رمز و فعال‌سازی یا قطع دسترسی پاسخ‌گویی فراهم شده است.
- حساب جدید وکیل به‌صورت پیش‌فرض غیرفعال است؛ مدیر باید پس از بررسی مستقل مدارک و صلاحیت حرفه‌ای، دسترسی را فعال کند.
- با قطع دسترسی، ورود جدید رد می‌شود؛ نشست‌های قبلی نیز در درخواست بعدی نامعتبر می‌شوند و ارسال پرسش جدید برای آن وکیل متوقف می‌شود.
- رمز عبور با `scrypt` و salt تصادفی هش می‌شود؛ نشست با توکن تصادفی و کوکی `HttpOnly`, `Secure`, `SameSite=Strict` نگهداری می‌شود.
- عملیات ایجاد وکیل، تغییر رمز و فعال/غیرفعال‌سازی در همان فهرست ممیزی مدیریتی ثبت می‌شوند.
- دکمه «بررسی تنظیمات سرور» فقط وضعیت وجود متغیرهای محیطی و اتصال `PING` به Redis را نشان می‌دهد و هیچ مقدار محرمانه‌ای را بازنمی‌گرداند. این بررسی باید روی Preview مستقرشده و با کلید مدیر معتبر انجام شود.

### محدودیت‌های باقی‌مانده پیش از عرضه عمومی

- بررسی اصالت پروانه وکیل هنوز فرایند برخط ندارد و باید توسط مدیر به‌صورت مستقل انجام شود.
- انقضای خودکار پرونده پرسش و پاسخ با TTL پیش‌فرض ۹۰ روز و قابلیت حذف دستی توسط مالک پیاده‌سازی شده است؛ اما مدت نگهداری نهایی، حذف از گزارش‌ها و نسخه‌های پشتیبان و الزامات قانونی باید پیش از عرضه عمومی بررسی و مستند شود.
- پنل‌های مدیریتی هنوز پشت سامانه ورود اختصاصی مدیر قرار نگرفته‌اند؛ `ADMIN_API_KEY` در مرورگر ذخیره نمی‌شود، اما کلید در حافظه صفحه و هدر درخواست استفاده می‌شود.
- آزمون اتصال واقعی Redis و موتور هوش مصنوعی باید روی Preview با متغیرهای محیطی همان محیط اجرا شود.
